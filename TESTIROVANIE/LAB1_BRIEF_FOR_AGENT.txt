ЛАБОРАТОРНАЯ РАБОТА №1 (ТПО) — бриф для агента
================================================

Контекст
--------
Студент переносит это задание в другой проект (папка TESTIROVANIE).
У агента там есть контекст диплома и доступ к коду/проекту диплома.
Объект тестирования: тема дипломного проекта (предпочтительно) ИЛИ сайт по варианту из методички.

Цель лабы
---------
Познакомиться с тестовой документацией и РАЗРАБОТАТЬ три вида документов:
  1) Тест-план (Test Plan)
  2) Чек-лист (Check-List)
  3) Четыре тест-кейса (Test Case) — минимум 4 штуки

Это НЕ кодинг и НЕ прогон автотестов. Нужны документы.

Формат сдачи (важно)
--------------------
Документы делать в .docx через Python-библиотеку python-docx.
Не ограничиваться одним .txt/.md: итог — готовые Word-файлы.

Рекомендуемые файлы в TESTIROVANIE (или подпапке LAB1):
  - 01_Test_Plan.docx
  - 02_Check_List.docx
  - 03_Test_Cases.docx
  - (опционально) Otchet_Lab1.docx — полный отчёт

Установка (если нужно):
  pip install python-docx

Что должно быть в каждом документе
-----------------------------------

1) ТЕСТ-ПЛАН
Структура (по методичке):
  - Введение / цель составления тест-плана
  - Описание объекта тестирования (система/приложение, стек, кратко что делает)
  - Список функций / компонентов, которые тестируем
  - Стратегия тестирования: какие виды тестов применяем к объекту
    (например: функциональное, UI/юзабилити, модульное; что НЕ делаем и почему —
     нагрузка/безопасность часто «не проводим из-за отсутствия ресурсов»)
  - Последовательность работ: подготовка → тестирование → анализ
  - Критерии начала тестирования
  - Критерии окончания тестирования
  - План работ (таблица: задача / время / дата начала / дата окончания)
  - Автоматизация (если уместно для диплома: что будет автоматом позже, что вручную)
  - Окружение (браузеры/ОС/устройства — если веб)

Ориентир по стилю: пример «Тест план asp.vstu.by.pdf» / «Тест план для интернет-магазина.pdf»
из исходной папки LAB1 курса ТПО.

2) ЧЕК-ЛИСТ
  - Набор пунктов «что проверить», без подробных шагов.
  - Таблица или нумерованный список по модулям/разделам продукта.
  - Покрыть ВСЕ основные модули диплома, не только один экран.
  - Можно группировать: авторизация, CRUD сущностей, навигация, валидация форм,
    поиск/фильтры, роли/права, UI, адаптив, сообщения об ошибках и т.д. —
    по реальному функционалу диплома.
  - Детальность умеренная: для учебного проекта не обязательно «полный промышленный»
    чек-лист на десятки страниц, но фокус не сужать до одной фичи.

Ориентир: «Полный чек-лист тестирования веб-приложения.pdf», «Чек-лист asp.vstu.by.pdf».

3) ТЕСТ-КЕЙСЫ (ровно минимум 4, лучше 4–6 качественных)
Каждый тест-кейс — отдельная таблица/блок с полями:
  - Идентификатор (TC-01, TC-02, …)
  - Приоритет (высокий/средний/низкий)
  - Связанное требование (если есть; иначе — ссылка на пункт чек-листа / модуль)
  - Модуль / подмодуль
  - Заглавие (суть)
  - Предусловия / исходные данные
  - Шаги + ожидаемый результат по каждому шагу (или шаги списком + общий ожидаемый результат)

Правило: пункты чек-листа — идеи; тест-кейсы — конкретная реализация идей.
Один пункт чек-листа можно раскрыть несколькими кейсами; для лабы достаточно 4 кейсов,
взятых из самых важных пунктов чек-листа (позитив + негатив желательно).

Отчёт по лабе (если делают Otchet_Lab1.docx)
--------------------------------------------
Обязательные разделы (методичка, введение):
  - Название лабораторной работы
  - ФИО студента и дата
  - Цель работы
  - Подробное описание действий и результатов (вставить/приложить тест-план,
    чек-лист, тест-кейсы; скриншоты — если есть что показать)
  - Выводы

Выводы: что узнали про тест-план / чек-лист / тест-кейс.
НЕ перечислять в выводах «я составил документы…» — это не вывод.

Контрольные вопросы (для самопроверки / если спросят)
------------------------------------------------------
1. Что такое тестирование ПО?
2. Какие разделы включены в план тестирования?
3. Что такое чек-лист?
4. Что содержит ожидаемый результат тест-кейса?
5. Что относится к атрибутам тест-кейса?

Как агенту выполнить задачу
---------------------------
1. Изучить дипломный проект: модули, роли, основные сценарии пользователя.
2. Сгенерировать 01_Test_Plan.docx под этот проект (python-docx).
3. Сгенерировать 02_Check_List.docx — покрытие всех ключевых модулей.
4. Сгенерировать 03_Test_Cases.docx — минимум 4 детальных тест-кейса.
5. По возможности собрать Otchet_Lab1.docx с целью и выводами.
6. Не выдумывать несуществующий функционал: опираться на реальный диплом.
7. Писать по-русски, деловым стилем учебной документации.

Технические заметки по python-docx
----------------------------------
- Использовать Document(), Heading, Paragraph, Table.
- Таблицы: план работ; чек-лист (№ | модуль | проверка | ...); шаги тест-кейса
  (шаг | действие | ожидаемый результат).
- Нормальные поля/отступы, заголовки уровней 1–2.
- Файлы сохранять в TESTIROVANIE (или TESTIROVANIE/LAB1).

Источник требований
-------------------
Методичка по ТПО.pdf — «ЛАБОРАТОРНАЯ РАБОТА №1 Тест-план, чек-лист и тест-кейс»
(содержание отчёта: план + чек-лист + четыре тест-кейса).
