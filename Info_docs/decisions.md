# Решения и причины

Зафиксированы по **текущему коду и скриптам сборки**, не по старым md.

## Qt 5.12, не Qt 6

Причина: поддержка **Windows 7**. Qt 6 её отрезал. В `CMakeLists.txt` это сказано явно. Установщик: `MinVersion=6.1sp1`. Toolset v141 совпадает с комплектом `msvc2017_64`.

## Visual Studio — основной билд, CMake — запасной

Реальная разработка и демо идут через `Vuzhyk.sln`. CMake не содержит всех cpp из `Vuzhyk.vcxproj` (нет задачника черепахи, PackageManager, HoverActivatedMenuBar). Менять только CMake — значит сломать «официальную» сборку или разъехаться с ней.

## Frameless окно + свой TitleBar

Нужны светлая/тёмная тема «под школу», кнопки как в современном IDE, Aero Snap поверх кастомного хрома (`WindowFrameOverlay`, обработка snap в `MainWindow`). Нативное окно Win32 с этим конфликтовало бы с темой.

## FilePicker отдельным exe

Нативные диалоги Windows (`GetOpenFileNameW` и т.д.) вынесены из Qt, чтобы обходить ограничения Qt-диалогов и DPI/кодировок. IDE стартует `FilePicker.exe` с аргументами `-e/-s/--dir`.

## Встроенный Python 3.8 рядом с exe

Школьный ПК часто без Python и без прав администратора. Бандл `Python38/` гарантирует «работает из коробки». Дополнительные версии — не официальные exe-инсталляторы, а **`.7z`**, чтобы распаковать 7za в `interpreters/` без интерактивного setup.

## `Lib/site-packages` у управляемых интерпретаторов

`site.getsitepackages()` на Windows часто указывает в AppData. Тогда «установили pyrob» и IDE его не видит, или пакеты разъезжаются между учениками. Решение: для layout с `Lib/` и для всего под `interpreters/` всегда использовать `{dir}/Lib/site-packages` (`PythonInterpreterPaths`).

## Маски pyrob* / turtlexy* при копировании библиотек

Версия в имени wheel не зашита. Перед копированием в другой интерпретатор удаляются старые каталоги с тем же префиксом, чтобы не держать две версии пакета.

## Синхронизация — отдельный C-сервер, не Qt в IDE

Учительский HTTP должен жить после закрытия IDE (автозагрузка, трей «Выключить»). Чистый WinAPI + Winsock проще для фонового процесса без Qt. IDE только пишет ini и стартует/убивает процесс. Zip пакетов — 7za, не встроенный zip Qt: одинаковый инструмент с клиентом ученика и проверка `7za t`.

## Пароль вкладки синхронизации — DPAPI

Не хранить пароль открытым текстом в QSettings. `CryptProtectData` привязан к пользователю Windows.

## Агент: ASK vs CODE и свой протокол правок

Встроенный чат не должен молча переписывать файл в режиме вопросов. CODE применяет структурированные блоки `<<<VUZHYK_EDIT`, а не «весь ответ = новый файл» (кроме fallback на одну markdown-ограду). HTTPS OpenRouter идёт через **WinHTTP** (`AgentHttps`), а не только `QNetworkAccessManager`, из‑за TLS на Win7 и контроля протокола.

## Браузер — расширение, не ядро

Qt WebEngine тяжелый и ломает компактную установку / Win7-сценарии. Компонент Inno `browser` опционален. Ядро IDE WebEngine не линкует (в VS-проекте Vuzhyk; CMake тянет WebEngine из‑за цели расширения).

## Демо — отдельные exe, не скрипты в IDE

Нужны предсказуемые ролики без настоящего Python/сети. Фейковый chrome 1440×900 (кроме полей 800×800). Запись **своим** H.264 (minih264e), без FFmpeg в зависимостях. Формат **yuv420p**, **60 fps**, limited-range BT.601 — чтобы плееры не «плыли» цветом и не ставили полный диапазон. Имена exe с номером 1…12 — порядок создания сцен для сортировки у человека.

Демо **не** линкуют `AgentPanel`/HTTPS: иначе тянется LM Studio и сеть.

## Справка HTML + PDF учебников

Интерактивные примеры и оглавление — `help/*.html` в `QTextBrowser`. Полные учебники Котова — PDF через SumatraPDF в `tools/pdf/`, без зависимости от внешнего Acrobat.

## Single-instance

Двойной клик по `.py` не должен плодить окна. `QLocalServer` передаёт путь в уже запущенный процесс.

## Debug-конфиг Vuzhyk на Release CRT

В `Vuzhyk.vcxproj` Debug часто собирается с `NDEBUG` и тем же Qt Release, чтобы не смешивать debug/release DLL Qt 5.12. Символы при этом могут быть включены. Не «исправлять» на полный debug Qt без необходимости — сломается деплой.
